# 四大黄金信号参考

用于把阶段计划、执行总结、监控模板和告警候选统一收敛到 Google SRE 的四大黄金信号。

## 信号定义

### Latency

- 关注请求、任务、队列、依赖调用的耗时
- 优先记录 `p50 / p95 / p99`、超时率、排队时间、关键链路慢点
- 典型产物：延迟基线、阈值、慢调用排查路径、用户可感知影响

### Traffic

- 关注请求量、吞吐量、消费速率、峰值模式、批处理规模
- 优先记录 `RPS/QPS`、任务量、业务峰值窗口、渠道占比、流量突增来源
- 典型产物：容量基线、峰值假设、限流点、发布窗口观察项

### Errors

- 关注失败请求、异常、重试、降级、业务失败率、告警噪声
- 优先记录错误率、错误分布、主要错误码、恢复动作、误报来源
- 典型产物：错误预算关注点、告警阈值、值班排查入口、业务受损面

### Saturation

- 关注 CPU、内存、磁盘、连接池、队列、线程池、第三方配额等资源逼近上限
- 优先记录利用率、饱和度、余量、扩容触发条件、手动缓解动作
- 典型产物：容量余量、扩容阈值、回滚条件、重大部署前检查项

## 计划编写规则

- 每个计划最多选择一个主信号：`golden_signal: latency|traffic|errors|saturation`
- 如果计划是横向整理、索引、文档装配类工作，可以不设置 `golden_signal`
- 计划任务应至少回答四件事：
  1. 当前信号现状是什么
  2. 风险点和业务影响是什么
  3. 阈值、告警或观察项是什么
  4. Runbook / monitoring / deployment 文档需要更新什么

## 执行与总结规则

- `SUMMARY.md` 应明确写出本计划聚焦的主信号
- 记录监控覆盖、候选告警、业务关注点和 runbook 影响
- 如果计划没有主信号，也要说明它支撑了哪类运维分析输出

## 与发布节奏的关系

- 手动部署也需要信号化分析
- 重点在发布前检查、发布后观测、异常时定位
- 运维文档在重大部署、运维策略变化、事故复盘后刷新即可，不必跟随每次代码提交
