## 回滚流程

### 自动回滚触发条件

| 触发条件 | 阈值 | 动作 |
|----------|------|------|
| 健康检查失败 | 连续失败 >3 次 | 立即回滚 |
| 错误率飙升 | 错误率 >5% | 立即回滚 |
| 响应时间恶化 | 超过基线 2 倍 | 告警并人工决策 |

### 手动回滚

```bash
# 回滚命令
[rollback command]

# 验证回滚结果
[verification command]
```

### 回滚决策树

```
发现问题
    -> 严重（服务不可用）？
       -> 是 -> 立即回滚，之后再调查
    -> 降级（部分功能受损）？
       -> 是 -> 评估影响
           -> 面向用户？ -> 回滚
           -> 仅内部？ -> 监控，并在 15 分钟内决定
    -> 轻微（外观或非阻塞问题）？
       -> 继续监控，在下次部署修复
```

## 环境变量

### 必需变量

| 变量 | 环境 | 说明 | 是否为 Secret |
|------|------|------|----------------|
| `DATABASE_URL` | 全部环境 | 数据库连接 | Yes |
| `API_KEY` | 全部环境 | 外部 API 密钥 | Yes |
| `NODE_ENV` | 全部环境 | 环境模式 | No |
| `LOG_LEVEL` | 全部环境 | 日志详细度 | No |

- 详细部署流程

  - 服务关键程度
  - 团队经验
  - 基础设施能力
  - 回滚要求

**部署前检查清单：**
- 按项目实际情况定制
- 覆盖所有关键检查
- 流程演变时同步更新

- 定义清晰触发条件
- 记录决策树
- 定期演练回滚

**环境变量：**
- 不要写入真实值
- 记录轮换周期
- 标明 secret 的存储位置

**Database Migrations：**
- 优先考虑向后兼容
- 先在 staging 验证
- 永远准备 rollback 方案

**部署后：**
- 定义 smoke tests
- 明确观察窗口
- 写清成功标准

</guidelines>
