## 事故分级

| 等级 | 定义 | 示例 | 响应时间 |
|------|------|------|----------|
| SEV1 | 全站不可用 / 关键数据风险 | 生产完全宕机 | 立即 |
| SEV2 | 严重功能降级 | 支付故障、认证故障 | 15 分钟内 |
| SEV3 | 部分功能受影响 | 某个区域功能异常 | 1 小时内 |
| SEV4 | 低影响问题 | 单个功能异常 / 次要 bug | 下一个工作日 |

## 常见问题

### 问题：服务无响应

**症状：**
- 健康检查失败
- 出现 502/503 错误
- 端点无响应

**诊断：**
```bash
# 查看服务状态
[status command]

# 查看日志
[log command]

# 查看资源使用
[resource command]
```

**处理步骤：**
1. 确认服务是否正在运行
2. 检查资源上限（CPU、内存）
3. 查看最近部署
4. 审查错误日志
5. 必要时重启服务
6. 如果由最近部署导致，执行回滚

**升级：** 15 分钟内未恢复则升级为 SEV1

---

### 问题：错误率过高

**症状：**
- 错误率 > 1%（warning）或 > 5%（critical）
- 4xx/5xx 响应增加
- 用户报告失败

**诊断：**
```bash
# 查看错误日志
[error log command]

# 按错误类型聚合
[group errors command]

# 查看最近改动
[deployment history]
```

**处理步骤：**
1. 识别错误模式
2. 查看最近部署
3. 检查外部依赖
4. 检查数据库连通性
5. 打 hotfix 或回滚
6. 监控错误率恢复情况

**升级：** 错误率 > 5% 且持续 > 5 分钟则升级为 SEV2

---

### 问题：响应时间变慢

**症状：**
- P95 延迟 > 阈值
- 用户反馈卡顿
- 出现超时错误

**诊断：**
```bash
# 查看响应时间分布
[latency command]

# 查看数据库查询耗时
[db query time command]

# 查看缓存命中率
[cache stats command]
```

**处理步骤：**
1. 找出慢接口
2. 检查数据库查询性能
3. 检查缓存效果
4. 检查资源争用
5. 必要时扩容
6. 优化慢查询

**升级：** P95 > 2s 且持续 > 10 分钟则升级为 SEV2

---

### 问题：数据库连接异常

**症状：**
- 连接超时错误
- “Too many connections” 错误
- 查询失败

**诊断：**
```bash
# 查看连接数
[connection count command]

# 查看数据库健康状态
[db health command]

# 查看锁情况
[lock check command]
```

**处理步骤：**
1. 检查连接池配置
2. 杀掉长时间运行的查询
3. 检查是否存在表锁
4. 重启连接池
5. 必要时扩容数据库

**升级：** 数据库不可达超过 5 分钟则升级为 SEV1

---

### 问题：内存 / CPU 耗尽

**症状：**
- 出现 OOM 错误
- 服务重启
- 性能变慢

**诊断：**
```bash
# 查看内存使用
[memory command]

# 查看 CPU 使用
[cpu command]

# 查看进程列表
[process command]
```

**处理步骤：**
1. 找出高资源占用进程
2. 检查是否存在内存泄漏
3. 扩容资源
4. 重启受影响服务
5. 调查根因

**升级：** 服务崩溃则升级为 SEV2

---

### 问题：外部服务故障

**症状：**
- 第三方 API 错误
- 支付处理失败
- 认证失败

**诊断：**
```bash
# 查看外部服务状态
[status check command]

# 查看错误响应
[error log command]

# 测试连通性
[connectivity test]
```

**处理步骤：**
1. 查看服务状态页
2. 启用 fallback / circuit breaker
3. 如可行切换到备用 Provider
4. 通知用户
5. 监控恢复

**升级：** 业务关键服务不可用则升级为 SEV2

## 维护流程

### 计划内维护

**维护前：**
- [ ] 提前 24 小时通知相关方
- [ ] 准备回滚方案
- [ ] 校验备份完整性
- [ ] 配置监控告警

**维护中：**
- [ ] 启用维护模式
- [ ] 执行维护任务
- [ ] 校验所有服务健康
- [ ] 关闭维护模式

**维护后：**
- [ ] 运行 smoke tests
- [ ] 持续监控 1 小时
- [ ] 记录变更
- [ ] 通知相关方维护完成

### 紧急维护

1. 立即发布维护通知
2. 启用维护模式
3. 执行必要修复
4. 校验并恢复服务
5. 进行事后复盘
