# 用户设置模板

用于生成 `.planning/phases/XX-name/{phase}-USER-SETUP.md`。

只记录 Claude 不能自动完成、必须由用户亲自操作的事项，例如：
- 创建外部服务账号
- 从控制台复制密钥
- 配置第三方平台面板

不要把 Claude 已经能自动完成的事情写进来。

---

## 文件模板

```markdown
# 阶段 {X}: 需要用户完成的设置

**生成时间：** [YYYY-MM-DD]
**阶段：** {phase-name}
**状态：** 未完成

以下事项需要用户手动完成，Claude 已经自动处理了所有可自动化部分。

## 环境变量

| 状态 | 变量名 | 来源 | 写入位置 |
|------|--------|------|----------|
| [ ] | `ENV_VAR_NAME` | [服务控制台 → 路径 → 值] | `.env.local` |
| [ ] | `ANOTHER_VAR` | [服务控制台 → 路径 → 值] | `.env.local` |

## 账号设置

[仅在需要创建新账号时保留]

- [ ] **创建 [Service] 账号**
  - 地址：[signup URL]
  - 如果已有账号可跳过

## 控制台配置

[仅在需要在外部控制台中配置时保留]

- [ ] **[配置项名称]**
  - 位置：[服务控制台 → 路径 → 设置项]
  - 设置为：[所需值]
  - 备注：[重要说明]

## 本地开发

[仅在需要本地辅助步骤时保留]

- [步骤 1]
- [步骤 2]

## 验证

完成设置后，运行：

```bash
# [验证命令]
```

预期结果：

- [成功时应看到什么]

---

**全部完成后：** 请把文件顶部状态改成“已完成”。
```

---

## 生成规则

- 当 PLAN.md frontmatter 中存在 `user_setup` 时生成
- 文件放在对应阶段目录，与 PLAN.md 和 SUMMARY.md 同级
- 标题和正文使用中文
- 变量名、命令、服务名保持原样

## 判断标准

下面这些内容才应该进 USER-SETUP.md：

| Claude 不能做 | 应写入 USER-SETUP.md |
|---------------|----------------------|
| 创建外部服务账号 | 是 |
| 从第三方控制台复制密钥 | 是 |
| 手动开启某个控制台开关 | 是 |
| `npm install`、写代码、建文件 | 否 |
| 自动跑验证命令 | 否 |
